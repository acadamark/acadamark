# Tag-forms reference

A per-tag matrix of which syntactic forms each Layer 1 vocabulary
element semantically supports. The general three-form grammar
(pipe form, slash form, long form) is described in `DESIGN.md`
§"Tag forms"; this document is the per-tag reference.

## How to read this

- **Pipe form** — `<tag attrs | content>`. Short-form with body
  content terminated by the closing `>`. Content is typically
  inline or short.
- **Slash form** — `<tag attrs />`. Short-form with no body content
  (void tags and attribute-only tags).
- **Long form** — `<tag attrs>content</tag>`. Content bounded by an
  explicit closing tag. The general default for content-bearing
  block elements. Two spellings: **multi-line** (closer on a later
  line, block position only) and **same-line** (opener and closer on
  one line, e.g. `<b>bold</b>` — recognized inline within a paragraph
  as well as on its own line). See `shorthand-syntax.md` §"Long-form tags".

| Marker | Meaning |
|---|---|
| ✓ | Supported and idiomatic for this element. |
| · | Supported but uncommon (rarely the natural authoring shape). |
| — | Unsupported (semantically meaningless for the element, or rejected by the parser/handler). |

**Disclaimer:** the matrix below is inferred from each vocab entry's
content model (`content.shape` / `content.becomes`), its
content-handler dispatch (`getContentHandler` / `dsl-registry`), and the typical
authoring patterns recorded in the vocab's `shorthand_examples`. The parser itself
accepts all three forms for any named tag at the grammar level (per
`DESIGN.md` §"Tag forms" and the "All tag forms work for every tag"
direction); this reference documents the *semantic* fit per element.
Where an element's handler rejects a form (e.g. an opaque-content
element with no body), that's noted in the per-row notes.

## Reference table

### Document containers

These are the top-level wrappers a document is rooted in. Authored
either directly (`<article>`, `<book>`) or implicitly via
`<meta type=...>`.

| Tag | Pipe | Slash | Long | Notes |
|---|---|---|---|---|
| `<article>` | · | — | ✓ | Pipe form valid as `<article | Title>` (title-after-pipe). Usually implicit via `<meta type=article>`. |
| `<book>` | · | — | ✓ | Pipe form valid as `<book | Title>` (title-after-pipe). Usually implicit via `<meta type=book>`. |
| `<book-part>` | · | — | ✓ | Pipe form valid via shorthand expansion (`<chapter | Title>`, `<part | Title>`, etc.). The shorthand expansion typically supplies title-after-pipe. |
| `<frame>` | ✓ | — | ✓ | Frameable; pipe form for short body, long form for multi-paragraph. |

`<sub-sub-section>`) is the canonical block-section structure;
each title element is the section's promoted title.

| `<section-title>` | — | — | — | Generated by the structural plugin from pipe/sigil title content; explicit-form escape hatch, not the authoring path. |
| `<section-subtitle>` | — | — | — | Generated wrapper. |

### Frameables (figures, tables, diagrams)

The frameable class shares an authoring shape (id, title, caption,
border, numbered). Each member has its own body shape — image source,
parsed table data, DSL diagram source, or inline SVG.

| Tag | Pipe | Slash | Long | Notes |
|---|---|---|---|---|
| `<fig>` | ✓ | ✓ | ✓ | Pipe form `<fig src=x.jpg | caption>` is most common for images. Slash form `<fig src=x.jpg />` for images without inline caption. Long form for non-image figures wrapping body content. `<figure>` is an authoring alias rewriting to `<fig>` at the gate. |
| `<svg>` | ✓ | — | ✓ | Opaque content (raw SVG source); pipe and long forms both work. |
| `<frame>` | ✓ | — | ✓ | Generic frameable container. Both forms work; border and numbered both default on (#272), switchable with `-border` / `-numbered`. |
| `<table>` | ✓ | — | ✓ | Pipe form `<table csv \| data>` is the qualifying-tag pattern for parsed data. Long form `<table>...HTML...</table>` is the raw-HTML escape hatch. |
| `<csv>` | ✓ | — | ✓ | Pipe form `<csv \| a,b,c>` for inline CSV. Long form for multi-line. Opaque content. |
| `<tsv>` | ✓ | — | ✓ | Same as `<csv>` with tab-separated content. |
| `<mermaid>` | ✓ | — | ✓ | Pipe form for short diagrams; long form for multi-line. External-DSL source. |
| `<abc>` | ✓ | — | ✓ | Pipe form for short ABC music notation; long form for multi-line. External-DSL source. |
| `<img>` | — | ✓ | — | Inline void element; slash form only. |

### Citations and cross-references

| Tag | Pipe | Slash | Long | Notes |
|---|---|---|---|---|
| `<cite>` | ✓ | ✓ | · | Slash form `<cite @key />` is the attribute-only authoring shape. Pipe form `<cite @key | author 2024>` for custom text. Long form rarely needed. |
| `<ref>` | · | ✓ | — | Slash form `<ref @id />` is the typical attribute-only shape. Pipe form for custom link text. |

### Structured-data containers (apparatus)

| Tag | Pipe | Slash | Long | Notes |
|---|---|---|---|---|
| `<meta>` | — | · | ✓ | Long form for child-tag authoring. Slash form effectively when invoked with kwargs only (e.g. `<meta type=book title="X" author="Y" />`). |
| `<author>` | — | · | ✓ | Same shape as `<meta>` — kwarg form lifts to child tags at the gate. |
| `<config>` | — | ✓ | ✓ | Slash form for pure-kwarg invocations (`<config citation-style="apa" />`). Long form when authoring structured options. |
| `<data>` | — | — | ✓ | Container for `<library>` and similar resource-list children. |
| `<library>` | ✓ | ✓ | — | Two forms. The **inline body** form `<library bibtex | …entries… >` is the canonical format-word form — the leading format word names the payload language and the BibTeX / CSL-JSON sits in the (opaque) body, which the interpreter reads as the citation payload. The **slash** form `<library src="refs.bib" />` instead loads an external file via `src`. |

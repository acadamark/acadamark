# `<cite>`

An inline citation reference to a bibliography entry. The author writes the citation key; the resolver generates the rendered citation marker according to the document's citation style.

## Semantic intent

`<cite>` is for citations to scholarly bibliography entries — references to other works in the document's bibliography. The element is HTML-native (HTML's `<cite>` represents "the title of a work") but enscribe uses it more broadly to mean "a citation to a bibliography entry, rendered according to the citation style."

For cross-references to numbered elements within the document (figures, equations, sections, notes), use `<ref>` instead. Citations point at external works; cross-references point at content within the document.

## Authoring

The basic form takes one or more citation keys as positional arguments:

```
<cite goodall2024>
```

The key (`goodall2024`) must match the id of a bibliography entry, whether the entry comes from an external `.bib` file, a `<library>` block in `<data>`, or a `<bib-entry>` element.

**Multiple citations grouped.**

```
<cite goodall2024 attenborough2020 darwin1859>
```

The resolver joins them with style-appropriate separators (semicolons in author-year, commas in numbered).

**Citation with locator.**

```
<cite goodall2024 page=42>
<cite goodall2024 page=42-45>
<cite goodall2024 chapter=3 section="3.2">
```

The locator information (page, chapter, section) is included in the rendered citation.

**Citation with prefix or suffix.**

```
<cite goodall2024 prefix="see also">
<cite goodall2024 prefix="cf." page=42>
<cite goodall2024 suffix="; emphasis added">
```

Prefix appears before the citation; suffix appears after.

**Per-citation style override.**

```
<cite goodall2024 style=footnote>
```

Overrides the document-level style for this citation only. Useful for mixed-style documents.

## Citation styles

The rendered output depends on the citation style. Common styles:

| Style | Example output |
|-------|----------------|
| `author-year` | `(Goodall 2024)`, `(Goodall 2024; Smith 2020)` |
| `numbered` | `[1]`, `[1, 2, 3]`, `[1-3]` |
| `footnote` | `¹` (with footnote at page bottom) |
| `endnote` | `¹` (with endnote at document end) |
| `inline-author-year` | `Goodall (2024) showed that...` (author becomes part of sentence) |

The document-level style is set in `<config>`:

```
<config>
  <citation-style | author-year>
</config>
```

Individual citations can override via the `style` kwarg.

## Resolution

The citation resolver looks up each key against the document's citation registry. The registry is built from:

- External bibliography file (`<bibliography source="refs.bib">`).
- Inline `<library>` blocks in `<data>`.
- Inline `<bib-entry>` elements in `<data>`.

If a key resolves to an entry, the citation renders normally. If a key doesn't resolve, the citation renders with a visible error marker:

```
<cite badkey>  →  [?badkey]
```

The error appears in the output rather than failing silently or breaking the build. This matches enscribe's principle that documents always render to something even when there are errors.

## Content

The element's content is optional and rarely used. When present, it overrides the automatically-rendered citation text:

```
<cite goodall2024 | the work by Goodall>
```

This is rare. The resolver-generated text is usually preferred because it stays consistent with the document's style.

## Attributes

`page`, `chapter`, `section` — locator information within the cited work.

`prefix` — text appearing before the citation marker.

`suffix` — text appearing after the citation marker.

`style` — override the document-level citation style for this citation.

The handler reads these and produces the appropriate output. They are not standard HTML attributes; they're enscribe-specific.

## JATS mapping

JATS uses `<xref ref-type="bibr" rid="...">` for inline citations.

| enscribe | JATS |
|-----------|------|
| `<cite goodall2024>` | `<xref ref-type="bibr" rid="goodall2024">(Goodall 2024)</xref>` |
| Multiple keys | Multiple `<xref>` elements grouped together |
| Page locator | `<xref ref-type="bibr" rid="..." page="42">` (or as part of the rendered text) |

The JATS exporter uses the resolved citation text as the `<xref>` content; the bibliography entry remains in `<ref-list>` referenced by `rid`.

## Render-mode lowering

`<cite>` is HTML-native; no lowering needed. The handler-generated content (the citation marker text) appears as the element's content. The `data-cite-keys` attribute preserves the original keys for downstream tooling.

## Authoring patterns

**Single citation in flowing prose.**

```
The argument is supported by recent evidence <cite goodall2024>.
```

**Multiple citations.**

```
This finding has been reported widely <cite goodall2024 attenborough2020 darwin1859>.
```

**Citation with page reference.**

```
For details on methodology, see <cite goodall2024 page=42>.
```

**Citation as part of a sentence (inline-author-year style).**

```
<cite goodall2024 style=inline-author-year> reported significant findings.
```

The author becomes part of the sentence rather than appearing parenthetically.
